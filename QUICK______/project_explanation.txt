RestoSoft - Project Explanation (Interview Ready)

Opening line:
basically restosoft is a resuarant management platform I've contributed around 80% of the development work on RestoSoft -it have  both a desktop billing pos system and a set of web applications.

1. Desktop POS Application (Electron-based)

- Works completely without internet - built using Electron, which gives access to Windows OS-level drivers directly
- Cloud sync engine - data automatically syncs from local SQLite to cloud MySQL once internet is available

- Inventory management and menu management modules
- Bulk menu upload feature
- Daily sales reports
- Multiple billing types - Dine In, Takeaway, Home Delivery, QSR - with both prepaid and postpaid options
- WhatsApp OTP integration and automatic e-bill/invoice generation
- Barcode scanner integration - scanning an item adds it directly to the cart
- Swiggy and Zomato integration - orders come in through a hub (like Urban Piper) and get pulled directly into both the desktop POS and web cashier app, so the client manages all orders from one place

2. Web Applications (Role-based)

- Admin - controls all settings, employee creation, permissions, and monitors everything centrally
- Cashier (Web) - same core features as desktop POS, but browser-based and requires internet; also receives Swiggy/Zomato orders
- Waiter - tablet-friendly, responsive app, optimized for speed with shortcut-based billing for quick order-taking
- Digital Menu - customer-facing app, similar to Swiggy, where customers place orders directly from their mobile browser

3. Tech Stack

- Frontend/Desktop: React.js, TypeScript, Electron.js
- Backend: Node.js, Express.js, PHP
- Databases: SQLite (local), MySQL (cloud)
- Integrations: Razorpay, WhatsApp, Swiggy, Zomato (via Urban Piper), AWS S3
